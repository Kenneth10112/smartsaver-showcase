Brief System Description for Reference

SmartSaver is a hub-and-module system for domestic energy management. A single Hub, built on an ESP32, reads wired sensors (motion, temperature and humidity, ambient light), maintains a DS3231 real-time clock that stores UTC (a local offset is applied for display and time-of-day rules), holds the automation rules, and serves its own configuration and monitoring dashboard. Remote Wireless Modules, built on ESP32-C3 boards, are flashed with one capability each — a 2-channel relay (IN1 and IN2 driven together) or a motion sensor — and locate the Hub with a verified 1–11 channel-hop discovery before pairing over ESP-NOW. ESP-NOW runs unencrypted in this version: broadcast HELLO/hello_ack discovery cannot use a multicast encryption key, so the pre-shared and local master keys remain defined but disabled. A relay or the Hub's buzzer acts as the actuator, and every wireless actuator reports its resulting state back; the wired buzzer path is implemented but the bench module produced no audible sound. A History Server has been reworked but is not yet fully implemented or deployed. It is intended to remain a Python standard-library service backed by SQLite, and its planned endpoint is https://smartsaveranalytics.me — a free domain registered through Namecheap with GitHub Education. Deployment is on hold while the design is being simplified. The local Hub, dashboard and rules do not depend on it, so the current build has no live savings dashboard. Savings, when implemented, are intended to be derived from appliance operating hours against a user-declared baseline, not from metered current. Infrared and servo actuation are reserved capability identifiers and are not implemented in this version.

A. Functional Suitability

Savings reporting is planned with the History Server but is not deployed in this build.
2Rule evaluation is correct: a satisfied trigger produces the configured action, and when several rules target the same appliance exactly one command is issued according to the defined priority order.

C. Reliability

The degree to which the system performs specified functions under specified conditions for a specified period.

3The system tolerates a Wireless Module going out of range, losing power or being removed, without disturbing the rest of the installation.
4The system recovers predictably after a power interruption, including restoring persisted configuration and automation rules.

D. Usability

The degree to which the system can be used by specified users to achieve specified goals effectively, efficiently and satisfactorily.

5An ordinary household occupant with no technical background can complete initial configuration through the Hub's captive-portal setup page without assistance.
6The Hub dashboard makes the current state of every part and appliance understandable at a glance.
7The registry-driven rule editor allows a valid automation rule to be built without knowledge of the underlying protocol or device identifiers.
8Applying a manual override, and understanding when automation will resume, is clear to the user.
9The interface is consistent in its layout and terminology across the pages a user has to visit.

E. Security

The degree to which the system protects information and data so that access is appropriate to the level of authorisation.

10Access to the Hub's dashboard is protected by credentials, and the session cannot be established without them.
11Wireless traffic between the Hub and its modules is unencrypted in this version. The broadcast-discovery limitation that forces this is documented, and the deployment is restricted to a trusted home network. Is that limitation and mitigation adequate?

G. Maintainability

The degree to which the system can be modified effectively and efficiently, including correction and improvement.

12Configuration is centralised and documented, so the system can be reconfigured without editing source code.

H. Portability

The degree to which the system can be transferred from one environment to another effectively and efficiently.

13The system can be installed in a different dwelling with a different number of rooms and appliances by adding or removing modules and adjusting configuration alone.
