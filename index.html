Overview

SmartSaver is a home energy system that automates the loads people usually leave running: lights, fans, appliances, and whatever else is plugged into a relay. It watches the signals a room already gives — occupancy, daylight, temperature, humidity, the clock — and switches only when the situation calls for it.

The hub keeps the decision loop inside the house. Rules run on the ESP32; the dashboard is for setup, visibility and manual override. If the internet disappears, the room is still in autopilot.

It is modular on purpose. A wired sensor is declared once, a wireless module is paired once, and the rules engine treats both as parts. Add a capability when you need it. Remove it when you do not.

The general flow

SmartSaver is used in four passes: read the room first, declare what is connected, add the automation, then handle the slower settings.

Software

From first boot to daily use, every screen is local to the Hub and served from the Hub. No account creation, no companion app, no waiting for a cloud round trip.

Wi-Fi provisioning
and dashboard login.

Power the Hub. Join the SmartSaver setup network. Provide the home Wi-Fi credentials, set a dashboard password, and let the Hub reboot onto the network. The dashboard appears at smartsaver.local.

It is deliberately a one-time flow. Wi-Fi credentials and the dashboard login stay on the device and are not part of a system backup.

A dashboard you check,
not manage.

The dashboard is where you look and where you occasionally step in — not another job. Every enabled part becomes a row on Home: temperature and humidity, light or dark, motion, relay state, RTC. Values update as readings arrive.

Manual override is part of the same surface. Give a load an explicit On or Off, watch the countdown, then clear overrides when you want the rules to take the room back. The automation keeps running underneath.

Hardware

The Hub is the fixed part. Everything else is chosen per room, so the system starts at the size of the problem instead of the size of a catalog.

Modular is a cost decision. A room that needs one motion sensor and one relay should not pay for a full sensor board. Buy the parts that room needs, declare them once, and add another sensor or relay later without replacing the Hub or rebuilding the rules.

The same registry also makes the system scale. Wired parts are declared in the checklist; wireless modules are paired over ESP-NOW. Add a second room, a second relay or a different sensor, and the rule builder sees the new part as another option. The automation grows one part at a time.

Future plans, clearly marked. Some catalog entries describe a future plan for if the system scales up to more sensor and actuator types. They are not part of the current tested build. They are labelled unimplemented and disabled until a working driver exists, so they cannot be mistaken for available hardware.

Rules

Rules are deliberately small: a condition on one part, and one command to one actuator. The constraint makes the system predictable, editable and easy to explain to the people who live with it.

Predefined rules,
already grounded.

The catalog is built from the parts currently on the Hub. Categories such as Security, Power Savings, Comfort and Lighting open into combinations that match the current registry.

Each choice is an ordinary rule bundle. Add it, then edit it like anything else. If a part exists only as a future catalog entry, the bundle is labelled unimplemented and cannot be selected.

Config

Config is a small grid of jobs: Wi-Fi, login, clock, backup, restart, reset. Each one opens its own panel. Nothing important is hidden inside a wizard you have to remember.

Backup the system,
not the credentials.

A backup carries parts, rules, paired devices and preferences. It deliberately does not carry Wi-Fi provisioning or the dashboard login, so a configuration can move between Hubs without carrying a network identity with it.

Restore replaces those system files, keeps the Hub on its current network, and reboots. It is a restore of the automation, not a factory clone.

Why it matters

The best automation is the one nobody has to think about. SmartSaver makes the room react to what is already happening, and makes every decision visible enough to trust or change.

Sense

Motion, light, temperature, humidity, time. Wired or wireless, all through one registry.

Decide

A rule engine that runs on the Hub, with priority order and manual overrides that always win.

Act

Relay, buzzer, lamp, fan. The command goes to the exact part the rule names.
